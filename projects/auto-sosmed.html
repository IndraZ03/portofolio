Auto Sosmed Metamorph

Otomatisasi unggahan Instagram melalui web yang menghubungkan MeteoFactory, Google Drive, dan Meta API. Mempermudah publikasi konten UPT dengan pilihan jenis konten yang fleksibel.

↓ Gulir untuk mengikuti alur proyek ↓

Kebutuhan Publikasi UPT

Padatnya konten yang harus diunggah oleh UPT memberikan ide untuk membuat otomatisasi unggahan konten Instagram.

Integrasi Sumber Konten

MeteoFactory dan Google Drive dihubungkan ke Meta API menggunakan web server untuk mendukung otomatisasi unggahan Instagram.

Web yang Fleksibel

Unggahan konten Instagram dapat dilakukan secara otomatis melalui web yang user-friendly dan fleksibel untuk menambahkan jenis konten.

Alur Kerja Sistem

How It Works

Enam tahap pemrosesan otomatis dari penerimaan berkas hingga pelaporan hasil. Alur memastikan hanya konten yang lolos filter dan aturan penjadwalan yang diproses ke platform Meta.

  1. 01
    Tahap 01 · Asupan

    Content Arrives

    Konten masuk melalui lampiran email IMAP atau folder lokal yang disinkronkan oleh Google Drive Desktop. Worker aplikasi memeriksa folder lokal hasil sinkronisasi, bukan melalui koneksi langsung ke cloud Google Drive.

  2. 02
    Tahap 02 · Validasi

    Rules & Validation

    Worker mencocokkan subjek email, nama berkas, format media, dan aturan saluran. Berkas yang tidak sesuai kriteria dilewati (skipped) dan tidak dipaksakan untuk terbit.

  3. 03
    Tahap 03 · Event

    Create Publication Event

    Media yang lolos disalin ke direktori penyimpanan tetap. Sistem membuat entri event baru di database dengan status SCHEDULED beserta target waktu publikasi.

  4. 04
    Tahap 04 · Penjadwalan

    Wait for the Right Time

    Scheduler berjalan secara periodik untuk memeriksa event berstatus SCHEDULED yang telah jatuh tempo, slot harian saluran, dan batasan batas laju publikasi.

  5. 05
    Tahap 05 · Publikasi

    Publish to Instagram

    Worker mempersiapkan media dan mengirimkan perintah penerbitan menggunakan Meta Graph API resmi. Status diperbarui selama proses pengunggahan berlangsung.

  6. 06
    Tahap 06 · Pencatatan

    Track the Outcome

    Hasil dicatat sebagai PUBLISHED atau FAILED lengkap dengan log audit. Sistem kemudian mengirimkan ringkasan status ke grup WhatsApp melalui GREEN-API.

Tahap 01 · Asupan

Content Arrives

Catatan sistem: Integrasi otomatisasi saat ini aktif untuk Instagram Feed. Jalur Threads belum diposisikan sebagai alur publikasi penuh secara otomatis.

Kapabilitas Utama

Key Features

Enam pilar teknis dalam arsitektur Auto-Sosmed yang mendukung keandalan asupan berkas, fleksibilitas jadwal, dan pemantauan terpusat.

FEATURE 01

Email Content Intake (IMAP)

Worker latar belakang secara berkala melakukan polling email baru via IMAP, memfilter subjek dan lampiran berdasarkan aturan saluran, lalu mengamankan berkas valid ke sistem.

  • Pencocokan subjek presisi (exact / contains) sesuai kebutuhan kanal.
  • Filter lampiran berbasis ekstensi media dan pola penamaan berkas.
  • Baseline UID terrekam untuk mencegah pemrosesan ulang email arsip lama.
FEATURE 02

Drive-Synced Folder Monitoring

Pemanfaatan Google Drive Desktop untuk sinkronisasi cloud ke folder lokal. Worker mendeteksi berkas baru langsung dari filesystem lokal tanpa ketergantungan API webhook eksternal.

  • Pemindaian lokal cepat tanpa mengonsumsi kuota API Google Drive.
  • Pemeriksaan stabilitas berkas untuk mencegah membaca file yang masih diunduh.
  • Pencatatan state file yang sudah diproses agar tidak terduplikasi.
FEATURE 03

Rule-Based Scheduling

Wizard saluran memungkinkan operator menetapkan aturan sumber, media target, format caption dinamis, dan jadwal publikasi spesifik dalam zona waktu WITA.

  • Wizard 4-langkah: Informasi, Sumber Konten, Konfigurasi Format, Konfirmasi.
  • Dua metode jadwal: penundaan adaptif setelah asupan atau waktu posting harian tetap.
  • Validasi slot harian untuk mencegah tabrakan jam tayang antar saluran.
FEATURE 04

Automated Instagram Publishing

Integrasi langsung ke Meta Graph API untuk publikasi otomatis berbagai tipe media visual dengan pipeline persiapan otomatis.

  • Mendukung single image, carousel multi-foto hingga 10 gambar, dan Story.
  • Video Reels didukung melalui pemrosesan dan verifikasi spesifikasi via FFmpeg.
  • Transisi status transparan: PROCESSING → UPLOADING → PUBLISHED.
FEATURE 05

Event Monitoring & Activity Logs

Dasbor monitoring menyajikan status setiap tahapan event secara komprehensif, dilengkapi jejak audit mendalam untuk mempermudah identifikasi masalah.

  • Siklus status lengkap: SCHEDULED, PROCESSING, UPLOADING, PUBLISHED, FAILED.
  • Pencatatan riwayat polling IMAP/Drive dan log respon dari API Meta.
  • Pencegahan retry buta: mendeteksi kegagalan parsial untuk verifikasi manual operator.
FEATURE 06

WhatsApp Process Notifications

Integrasi GREEN-API memberikan pembaruan instan ke grup WhatsApp terkait jalannya proses publikasi, memberikan ketenangan tanpa perlu memantau dasbor terus-menerus.

  • Notifikasi otomatis pada awal pemrosesan dan saat unggahan selesai.
  • Laporan kegagalan segera dikirimkan jika terjadi penolakan format dari Meta API.
  • Komunikasi asinkron: kegagalan transmisi WhatsApp tidak menggugurkan hasil posting.

DECISION 01

PostgreSQL-Backed Queue

Antrean event dijadwalkan dan disimpan langsung di PostgreSQL menggunakan Prisma, menghindari kompleksitas operasional message broker tambahan seperti Redis atau RabbitMQ.

DECISION 02

Worker Isolation

Worker asupan (IMAP & Folder Poller) dan worker publikasi berjalan sebagai proses mandiri. Kegagalan rendering pada frontend web tidak memutus siklus pemrosesan latar belakang.

DECISION 03

Filesystem-Based Drive Sync

Memanfaatkan aplikasi Google Drive Desktop bawaan OS untuk sinkronisasi cloud, sehingga worker cukup memindai disk lokal tanpa risiko terhambat kuota API Google Drive.

Engineering Insights & Tradeoffs

Database-Backed Queue

Pemanfaatan PostgreSQL secara langsung sebagai antrean event mengeliminasi ketergantungan pada message broker terpisah (seperti Redis atau Kafka), menyederhanakan arsitektur pemeliharaan.

Separated Background Execution

Dasbor web hanya berfungsi sebagai panel kontrol deklaratif; seluruh asupan berkas dan publikasi dieksekusi secara asinkron oleh worker terpisah yang tahan terhadap gangguan koneksi web client.

Local Media, Relational Meta

Berkas media fisik disimpan di penyimpanan disk lokal terstruktur, sementara database hanya mengelola status dan path, menjaga ukuran basis data tetap ringan dan cepat.
