Web BMKG Kaltim & Sistem Pelayanan Data

Pengembangan website UPT BMKG Kaltim untuk memanfaatkan VPS dan domain yang telah tersedia, dengan menggabungkan data dari API BMKG pada kaltim.bmkg.go.id.

↓ Gulir untuk mengikuti alur proyek ↓

VPS & Domain Belum Dimanfaatkan

Stasiun Meteorologi Kelas I Sultan Aji Muhammad Sulaiman Sepinggan belum memiliki layanan web, meskipun VPS dan domain sudah diberikan oleh Direktorat Jarkom. Domain sempat dinonaktifkan oleh pusat karena tidak dimanfaatkan.

Penugasan Pengembangan

Dengan latar belakang kompetensi di bidang web, saya diberi tugas oleh Ketua Tim Teknisi untuk membuat website UPT BMKG Kaltim.

Integrasi API BMKG

Website kaltim.bmkg.go.id dikembangkan dengan menggabungkan data dari API BMKG.

How It Works · Tiga jalur layanan

Dari sumber menuju layanan publik.

Portal menyajikan informasi resmi, menerbitkan produk yang telah disiapkan, dan melayani permohonan data. Bukan mesin yang menghitung prakiraan cuaca.

Automated Product Intake

  1. 01
    Tahap 01 · Sumber produk

    Products Are Prepared

    Forecaster atau MeteoFactory menyiapkan produk cuaca sebelum masuk portal. Web berfokus pada distribusi produk jadi.

  2. 02
    Tahap 02 · Dua pintu masuk

    Products Enter the System

    Email lampiran masuk melalui listener IMAP. Unggahan langsung MeteoFactory memakai jalur berbeda; kedua jalur tidak berbagi folder keluaran yang sama.

  3. 03
    Tahap 03 · Background listener

    Listener Detects Updates

    Proses IMAP terpisah dari HTTP server mencocokkan subject terkonfigurasi, memilih email terbaru per subject berdasarkan UID, dan mengambil lampiran valid.

  4. 04
    Tahap 04 · Media processing

    Media Is Prepared & Stored

    mailparser mengekstrak PNG, JPEG, WEBP, atau PDF. Sharp menormalisasi gambar ke PNG dan menangani background key produk tertentu; hasil jalur IMAP disimpan pada filesystem.

  5. 05
    Tahap 05 · File delivery

    Web Serves the Latest Product

    API pembaca memindai folder, mengurutkan berkas, dan memakai mtime untuk cache busting. Daftar unggahan MeteoFactory dibaca terpisah dari media IMAP.

  6. 06
    Tahap 06 · Public delivery

    Public Audiences Explore

    Pengunjung membaca produk pada halaman prakiraan, infografis, display publik, dan halaman relevan lainnya.

Product intake

Products Are Prepared

Weather Information

Tidak semua informasi masuk melalui email. Pembacaan API langsung/proxy dan sinkronisasi terjadwal memiliki jalur masing-masing.

  1. External & Observational Data

    Feed BMKG untuk prakiraan, nowcast, dan gempa; sumber radar, Sipongi, ECMWF, serta Himawari untuk produk terkait.

  2. Fetch, Sync & Processing

    Feed dibaca langsung atau melalui proxy. Cron/worker menyiapkan radar, hotspot, wind JSON, serta GeoHotspot ke file atau DB sesuai produknya.

  3. Map & Public Display

    Portal menyajikan informasi, media, dan overlay. Jalur ini tidak dipaksa melewati IMAP dan bukan simulasi WRF.

Data Services

Permohonan tersimpan melalui Prisma/MySQL. Proses layanan terpisah dari publikasi lampiran cuaca.

  1. 01
    Layanan 01 · Akun

    Applicant Signs In

    Pemohon masuk melalui konteks pelayanan, dengan verifikasi email dan captcha pada alur akun.

  2. 02
    Layanan 02 · Jenis

    Choose Request Type

    Pilih INFORMASI untuk layanan berbayar atau NOL_RUPIAH sesuai jenis permohonan.

  3. 03
    Layanan 03 · Pengajuan

    Submit Application

    Pemohon memilih layanan dan stasiun, mengisi kebutuhan, lalu melampirkan berkas yang diperlukan.

  4. 04
    Layanan 04 · Verifikasi

    Officer Review

    Petugas DATIN memeriksa kelengkapan dan menentukan kelanjutan permohonan.

  5. 05
    Layanan 05 · Conditional payment

    Payment When Required

    Untuk INFORMASI, petugas memasukkan kode billing SIMPONI secara manual. Bukti pembayaran diunggah lalu dikonfirmasi. NOL_RUPIAH melewati tahap ini.

  6. 06
    Layanan 06 · Hasil

    Data Delivery & Review

    Petugas mengunggah hasil. Pemohon dapat menerima atau menolak hasil dan memberikan catatan.

  7. 07
    Layanan 07 · Penyelesaian

    Feedback & Completion

    SKM wajib diisi sebelum penyelesaian. Status berakhir COMPLETED dan hasil dapat diunduh sesuai alur layanan.

Key Features · Public & operational needs

Informasi, produk, dan pelayanan.

Enam chapter memperlihatkan kebutuhan pengunjung, forecaster, pemohon, dan petugas melalui jalur yang berbeda.

FEATURE 01 / REGIONAL WEATHER

Regional Weather Information

Informasi cuaca regional terkumpul dalam satu portal: prakiraan per jam untuk kabupaten/kota dan kecamatan, nowcast Kaltim, gempa terkini, serta PM2.5 melalui proxy.

  • Data berasal dari feed/API resmi dan layanan terkait.
  • Web menyajikan hasil, tidak menghitung prediksi sendiri.
FEATURE 02 / PRODUCT PUBLISHING

Automated Weather Product Publishing

Produk siap tayang tidak perlu dipindahkan satu per satu dari mailbox. Listener IMAP menyaring subject, mengekstrak lampiran, dan menormalisasi gambar.

  • Mendukung PNG, JPEG, WEBP, dan PDF; Sharp menangani gambar.
  • ADMIN mengatur subject dan memantau proses/log; hasil IMAP berupa file.
FEATURE 03 / AVIATION & OBSERVATION

Aviation & Observation Products

Produk radar dan analisis radiosonde disajikan untuk kebutuhan pembacaan observasi tanpa membuka sistem pengolahnya.

  • Radar Balikpapan: CMAX, CMAX-HWIND, PAC06H, PAC24H dengan refresh berkala.
  • Unggah dan arsip radiosonde PDF dengan retensi tujuh hari.
FEATURE 04 / GEOSPATIAL

Geospatial Monitoring

Peta memberi konteks spasial melalui hotspot Sipongi, partikel angin ECMWF yang disiapkan cron, serta GeoHotspot berbasis anomali termal Himawari dan batas administrasi.

  • GeoHotspot dan modul Koordinat Hotspot merupakan kemampuan berbeda.
  • Visualisasi observasi bukan jaminan deteksi kebakaran sempurna.
FEATURE 05 / PUBLIC DATA SERVICES

Public Data Request Services

Pemohon mengikuti status permohonan dari pengajuan hingga hasil, sementara DATIN memegang keputusan review dan konfirmasi layanan.

  • Jenis INFORMASI dan NOL_RUPIAH dengan cabang pembayaran berbeda.
  • Billing SIMPONI manual, review hasil, SKM wajib, dan pengunduhan.
FEATURE 06 / CONTENT & OPERATIONS

Content, Backoffice & Public Display

Pengelolaan berita/artikel, approval konten, IKM, audit aktivitas, dan scene display mendukung proses editorial serta operasional.

  • Halaman publik dibedakan dari backoffice berakses terbatas.
  • Display menyusun produk dalam scene sesuai pengaturan.
System Architecture · Three pillars, distinct paths

Portal, intake, dan layanan data.

Ringkasan konseptual dari brief proyek. API langsung/proxy, listener IMAP, unggahan MeteoFactory, dan scheduled jobs tetap memiliki jalur tersendiri.

Public Portal

Input: halaman, produk, peta. Output: permintaan informasi publik.

Pengunjung bukan pengguna bebas backoffice.

Peran: penyajian React dan handlers web.

Input: API resmi, file lokal, dan data layanan. Output: halaman/produk serta workflow pemohon dan petugas.

Bukan worker IMAP atau mesin forecast.

Input: feed/API sumber. Output: informasi dibaca langsung atau melalui proxy sesuai produk.

Jalur ini tidak melewati listener IMAP.

Product Intake

Input: mailbox, subject terkonfigurasi, latest UID. Output: file produk dan log.

Proses terpisah dengan PID lock dan reconnect/backoff; tidak menulis lampiran ke MySQL.

Input: unggahan produk jadi. Output: berkas pada public/uploads/produk/.

Berbeda dari mailbox dan folder keluaran IMAP.

IMAP: public/produk/. Upload: public/uploads/produk/.

Radar, radiosonde, wind JSON, dan artefak geospasial memakai jalur terkaitnya sendiri. API pembaca menyajikan file; bukan object storage atau antrean DB.

Observation & Geospatial

Input: sumber observasi terkait. Output: file atau MySQL sesuai job.

GRIB2/ecCodes menyiapkan wind JSON; worker Python GeoHotspot menyiapkan anomali termal Himawari. Bukan semua data melewati satu pipeline.

Data Request Service

Input: permohonan, lampiran, keputusan petugas. Output: status dan hasil layanan.

NextAuth memisahkan konteks sesi umum, pelayanan, dan datacenter. SIMPONI diinput manual; authentication dan endpoint hardening tetap pertimbangan berkelanjutan.

Input/output: pengguna, permohonan, konten, serta observasi sesuai modul.

Prisma dipakai pada layanan data; beberapa modul observasi memakai mysql2 langsung. Tidak menyimpan file produk IMAP sebagai jalur ingestion.

  • Pengunjung ↔ Next.js · halaman dan interaksi
  • Feed/API → Next.js · direct read atau proxy
  • Listener IMAP → public/produk/ · file dan log, tanpa DB
  • MeteoFactory → public/uploads/produk/ · jalur unggahan terpisah
  • File lokal → API pembaca → halaman publik
  • Cron/worker → file produk sesuai sumber
  • Job terkait → MySQL · observasi sesuai modul
  • Pemohon / DATIN ↔ handlers Next.js
  • Layanan web ↔ MySQL · permohonan melalui Prisma

Engineering decisions

01 / FILE-BASED PUBLISHING

Media bukan workflow DB

IMAP menerbitkan file dan log; status permohonan masuk MySQL melalui layanan data. Folder unggahan MeteoFactory tetap berbeda.

02 / BACKGROUND PROCESSING

Worker di luar request

Listener, cron, dan pemrosesan ilmiah dipisahkan dari penyajian halaman publik.

03 / HUMAN REVIEW

Layanan tetap melalui petugas

DATIN memverifikasi permohonan dan billing SIMPONI manual; sistem tidak mengklaim pembayaran otomatis.

Tech Stack · Product technologies

Web delivery dan pemrosesan khusus.

Stack aplikasi BMKG menurut brief proyek, bukan dependensi situs portofolio statis ini. Provider data dikelompokkan sebagai integrasi.

01 · Application & UI02 · Persistence03 · Background jobs04 · Auth & services05 · Integrations
01 / APPLICATION & UI

Next.js, React & TypeScript

Next.js 16.1.4 App Router, React 19.2.3, dan TypeScript 5.x untuk halaman, SSR, route handlers, serta logika server/client.

UI & geospatial tools

Tailwind CSS 4 dan Radix UI untuk styling/primitives; Motion / Framer Motion 12 dan Embla Carousel 8.6 untuk interaksi. Leaflet, React Leaflet, dan Canvas/WebGL terdapat pada modul peta terkait; bukan berarti semua halaman memakai React Leaflet.

02 / DATA & PERSISTENCE

MySQL, Prisma & Local Files

MySQL menyimpan data operasional. Prisma 5.22 dan mysql2 menangani akses sesuai modul. File media tetap pada filesystem lokal.

Storage boundaries

Produk IMAP, unggahan, radar, radiosonde, dan file ilmiah menggunakan jalur file terkait. MySQL menyimpan pengguna, permohonan, konten, serta observasi; bukan lampiran produk IMAP.

03 / BACKGROUND PROCESSING

Node.js, IMAP & Python

Node.js 24.14.0 menurut brief, tsx untuk scripts TypeScript, imap/mailparser untuk mailbox, serta Sharp untuk normalisasi gambar.

Scheduled & scientific work

Cron dan shell menjalankan sinkronisasi radar, hotspot, dan ECMWF. Python 3/ecCodes memproses GeoHotspot serta GRIB2. Worker berdiri terpisah dari HTTP server, tanpa klaim queue terdistribusi.

04 / AUTH & SERVICE WORKFLOWS

NextAuth.js & Service Tooling

NextAuth.js 5 beta untuk sesi berbasis konteks; jose/bcryptjs untuk token dan hashing. ALTCHA serta Cloudflare Turnstile menangani challenge pada alur terkait.

Email & documents

Nodemailer dan React Email untuk status/verifikasi. jsPDF, pdfjs-dist, JSZip, dan docx untuk bukti, preview, unduhan, serta dokumen layanan. Penggunaan library tidak menjadi jaminan security maturity.

05 / EXTERNAL INTEGRATIONS · NOT LIBRARIES

BMKG, ECMWF, Sipongi & Himawari

Feed cuaca/peringatan/gempa BMKG; ECMWF IFS untuk angin; Sipongi dan Himawari untuk produk geospasial terkait; provider PM2.5, radar, serta radiosonde untuk observasi.

Integration boundaries

Sumber berbeda memakai direct API/proxy, cron, worker, atau unggahan. Portal tidak membuat semua prakiraan sendiri, dan tidak memanggil layanan produksi saat case study ini dibaca.

One app, multiple audiences

Next.js melayani publik, pemohon, dan backoffice dengan batas sesi. File-based media publishing serta background jobs khusus menjaga tanggung jawab web pada penyajian dan interaksi, bukan komputasi forecast.
