PETA SEBARAN HOTSPOT

Peta sebaran hotspot untuk mempermudah Tim Datin dan stakeholder dalam mendeteksi titik panas, dilengkapi rute langsung Google Maps pada setiap titik hotspot serta overlay angin dan area konsesi untuk mendukung OMC dan water bombing.

↓ Gulir untuk mengikuti alur proyek ↓

Kebutuhan Tim Datin

Selama ini, plotting hotspot masih dilakukan secara manual dan harus menjalankan script yang memakan waktu untuk mengolah datanya.

Ketua Tim Datin mengajak saya mengembangkan peta sebaran hotspot agar Tim Datin dan stakeholder dapat lebih cepat serta mudah mendeteksi titik panas.

Akses Rute Google Maps

Klik titik hotspot untuk membuka pop-up informasi, lalu pilih tombol Buka di Google Maps untuk melihat lokasi hotspot tersebut beserta rute menuju titiknya.

Overlay Angin & Area Konsesi

Overlay angin dan area konsesi ditambahkan untuk mendukung Operasi Modifikasi Cuaca (OMC) dan water bombing.

How It Works · From sync to interactive map

Sinkronisasi data, konteks di peta.

Modul Koordinat Hotspot pada web BMKG Kaltim memisahkan snapshot terbaru, produk peta wilayah, angin model, dan histori. Visual berikut merupakan ilustrasi statis, bukan data live.

  1. 01
    Tahap 01 · Scheduled ingestion

    Scheduled Data Sync

    Cron mengambil TSV hotspot dari sumber FTP BMKG pada menit 05 dan 35. Bila file belum tersedia, job mencoba tanggal sebelumnya dengan batas tertentu.

  2. 02
    Tahap 02 · Parse & validate

    Validate the Incoming Points

    Parser memeriksa struktur TSV, koordinat, wilayah KALIMANTAN TIMUR, tanggal, dan confidence. Titik tidak valid dilewati; validasi format bukan jaminan kejadian kebakaran.

  3. 03
    Tahap 03 · Persist snapshot

    Keep the Latest Snapshot

    Hasil terbaru di-upsert ke MySQL hotspot_data pada satu row id=1. Kegagalan sinkronisasi tidak menghapus snapshot terakhir; halaman realtime tidak mengunduh FTP pada setiap kunjungan.

  4. 04
    Tahap 04 · Map products

    Prepare Regional Maps

    Renderer Python menghasilkan gambar peta wilayah dan PDF. Cache berdasarkan hash menghindari rendering ulang yang tidak perlu; manifest terbaru dipublikasikan secara atomik.

  5. 05
    Tahap 05 · Separate wind branch

    Align Model Wind

    Setelah sync hotspot berhasil, job angin mengambil ECMWF IFS U10/V10. Waktu valid diselaraskan dengan interpolasi atau nearest sesuai kebutuhan; wind.json ditulis atomik. Kegagalan angin tidak menggagalkan hasil hotspot.

  6. 06
    Tahap 06 · Client rendering

    Serve the Interactive Map

    API menyajikan snapshot MySQL, GeoJSON lokal, dan wind JSON melalui jalur terpisah. Leaflet mengelola marker/popup WITA dan layer konteks; canvas WebGL khusus merender partikel angin.

  7. 07
    Tahap 07 · Explore & export

    Explore History & Export

    Pengguna memilih rentang histori hingga 31 hari, konteks konsesi/gambut, galeri peta wilayah, atau ekspor PDF. Histori memuat tanggal yang belum tercache hingga 10 tanggal per request dan menonaktifkan angin.

Data lifecycle

Scheduled Data Sync

Snapshot terakhir tetap berguna saat sumber gagal, dengan timestamp yang harus dibaca sesuai konteks. Koordinat Hotspot berbeda dari GeoHotspot termal Himawari B07. Angin model dan polygon konsesi tidak membuktikan penyebab kebakaran atau legalitas wilayah.

Key Features · Cartographic chapters

Baca titik, telusuri konteks.

Enam kemampuan untuk membaca snapshot, membandingkan histori, dan mengakses produk peta tanpa mencampur sumber datanya.

FEATURE 01 / REALTIME SNAPSHOT

Real-time Hotspot Map

Peta Leaflet pada imagery basemap menampilkan marker confidence rendah/hijau, sedang/kuning, dan tinggi/merah. Popup menyediakan detail titik dan tautan Google Maps.

  • Koordinat, kab/kota, kecamatan, satelit, confidence, serta timestamp WITA.
  • Refresh antarmuka setiap lima menit saat realtime, bukan streaming sensor per detik.
FEATURE 02 / HISTORICAL EXPLORER

Historical Hotspot Explorer

Rentang hingga 31 hari menggabungkan titik dari tanggal terpilih. Tanggal yang belum tersedia di database dapat diambil dari arsip sumber, hingga 10 tanggal per request.

  • Mode histori dan realtime memiliki kebutuhan waktu yang berbeda.
  • Angin mati saat histori dan kembali ke kondisi semula saat realtime.
FEATURE 03 / ECMWF WIND

ECMWF Wind Overlay

Komponen U10/V10 ECMWF IFS 0.25° disiapkan cron lalu divisualkan sebagai partikel melalui canvas GPU WebGL khusus.

  • Default aktif pada realtime, terpisah dari lifecycle marker Leaflet.
  • Fail-soft: kegagalan layer angin tidak menghilangkan titik hotspot.
FEATURE 04 / SPATIAL CONTEXT

Concessions & Peatland Context

Overlay palm, pulpwood, logging, mining, dan gambut dilengkapi batas kabupaten/kota serta delineasi IKN untuk membantu membaca konteks spasial.

  • GeoJSON lokal disaring menurut cakupan spasial.
  • Izin tambang dengan tanggal akhir tidak aktif tidak ditampilkan; data tetap snapshot.
FEATURE 05 / CARTOGRAPHIC EXPORT

Regional Maps & PDF Reports

Peta wilayah dirender Python menjadi gambar dan PDF setelah sinkronisasi. Galeri mengambil hasil dari cache serta manifest terbaru.

  • Laporan peta regional diunduh dari hasil server.
  • jsPDF di browser mengekspor tabel titik A4 landscape sesuai mode realtime/histori.
FEATURE 06 / ENGINEERING RELIABILITY

Resilient Data Refresh

Cron menit 05/35 memperbarui snapshot untuk API. Fallback sumber/tanggal, cache berkas, dan publikasi atomik membatasi dampak kegagalan alur terpisah.

  • Snapshot terakhir tidak dihapus ketika sinkronisasi gagal.
  • Wind job dicoba setelah hotspot sukses; kegagalan angin tidak membatalkan hasil hotspot.
System Architecture · Sources to client

Empat domain, jalur terpisah.

Ringkasan konseptual berdasarkan brief modul: sumber eksternal, processing, persistence/API, dan visualisasi browser. Tidak ada API produksi yang dipanggil untuk menggambar diagram.

01 · External data

Output: TSV hotspot untuk sync terjadwal atau tanggal histori yang belum tercache.

API realtime tidak memanggil FTP; alamat host dan akses sumber tidak dipublikasikan.

Output: komponen angin model untuk job terpisah.

Bukan inferensi arah kebakaran, asap, atau observasi angin bersamaan dengan tiap titik.

Output: konteks geografis melalui pembaca GeoJSON/konsesi.

Data snapshot lokal, disaring cakupan dan status tanggal izin terkait. Tidak tersinkron GIS eksternal saat halaman dibuka.

02 · Scheduled processing

Input: hotspot TSV. Output: MySQL snapshot dan data untuk renderer wilayah.

Cron berjalan menit 05/35. Wind job hanya dicoba setelah hotspot sukses; kegagalan wind diisolasi.

Input: data hotspot hasil sync. Output: gambar wilayah, PDF, dan latest.json.

Content cache membatasi rendering ulang; manifest terbaru dipublikasikan atomik.

Input: GRIB2 U10/V10 serta target waktu. Output: wind.json atomik.

Python/ecCodes mendekode data; interpolasi/nearest menyelaraskan waktu bila diperlukan. Kegagalan angin tidak menggagalkan hotspot.

03 · Persistence & APIs

Input: satu row snapshot diperbarui cron. Output: titik terbaru untuk browser.

mysql2 langsung, bukan Prisma. Tidak mengunduh FTP ketika endpoint realtime dibaca.

Input: cache gambar/PDF, latest.json, wind.json, dan GeoJSON lokal.

Output: API pembaca masing-masing produk, bukan satu file gabungan. Wind API membaca JSON dan memvalidasi ukuran grid; mtime cache dipakai pada layer terkait.

Input: rentang hingga 31 hari. Output: gabungan tanggal histori.

Tanggal belum tercache dapat diambil dari FTP hingga 10 tanggal per request. Bukan salinan event stream dari row snapshot.

04 · Client visualization

Input: snapshot/histori, GeoJSON, wind JSON, dan hasil peta regional.

Output: peta interaktif serta ekspor tabel PDF. Leaflet imperative mengelola marker/layer; engine canvas GPU khusus menggambar angin, bukan plugin React Leaflet.

Histori menonaktifkan angin. UI realtime memperbarui tiap lima menit.

  • FTP TSV → scheduled sync dan validasi
  • Sync → MySQL snapshot → realtime API
  • Data hasil sync → Python regional renderer
  • Renderer → cache gambar/PDF dan manifest atomik
  • Hotspot sync sukses → mencoba wind job
  • ECMWF GRIB2 → ecCodes dan temporal alignment
  • Wind job → atomic wind.json → wind API
  • GeoJSON lokal → pembaca konteks spasial
  • Snapshot API → Leaflet markers
  • API produk terpisah → peta, WebGL, dan galeri
  • Browser ↔ history API / MySQL per tanggal
  • Histori ↔ FTP · hanya tanggal belum tercache, maksimal 10 per request

01 / APPLICATION

Next.js, React & TypeScript

Next.js 16 App Router untuk halaman publik dan route handlers. React/TypeScript mengelola UI; Node.js menjalankan scripts terjadwal.

How it’s used

Frontend membaca API snapshot dan histori. Pemrosesan sumber dilakukan job terpisah, bukan unduhan FTP pada setiap kunjungan realtime.

02 / GEOSPATIAL UI

Leaflet 1.9.4 & GeoJSON

Leaflet imperative mengatur marker, popup, panes, serta overlay batas dan konsesi. Esri World Imagery berperan sebagai basemap, bukan library pemrosesan.

How it’s used

GeoJSON merupakan data konteks lokal. Lifecycle marker tidak dicampur dengan rendering angin; modul ini tidak dinyatakan memakai React Leaflet.

03 / ANIMATION & WIND

Custom WebGL & Canvas

Engine GPU khusus merender partikel dari U10/V10. ECMWF IFS 0.25° merupakan integrasi sumber data, bukan engine animasi.

How it’s used

Wind JSON disiapkan cron; canvas terpisah dari marker Leaflet. Bukan Windy API, pySTEPS, atau model prediksi penyebaran api.

04 / DATA & STATE

MySQL, mysql2 & Local Files

mysql2 mengakses snapshot terbaru dan histori per tanggal secara langsung. JSON/file lokal menyimpan angin, peta regional, dan konteks geografis.

How it’s used

hotspot_data id=1 untuk snapshot, hotspot_history untuk source date. Tidak memakai Prisma pada modul ini, dan tidak mengklaim cloud object storage.

05 / DATA PROCESSING

Python, ecCodes & Shell Cron

curl/shell dan scripts TypeScript menangani sinkronisasi sumber. Python/ecCodes mendekode GRIB2 serta menyelaraskan angin model.

How it’s used

Hotspot divalidasi sebelum snapshot diperbarui. Wind job dicoba setelah sync hotspot sukses, dengan kegagalan terpisah. Versi Python, Node.js, dan MySQL tidak ditebak.

06 / CARTOGRAPHIC EXPORT

Matplotlib & jsPDF 4.2.1

Matplotlib menghasilkan peta wilayah di Python. jsPDF mengekspor tabel titik A4 landscape di browser sesuai mode aktif.

How it’s used

Gambar/PDF regional memakai cache server dan manifest terbaru. Ekspor tabel frontend bukan proses yang sama dengan renderer regional Python.

07 / RELIABILITY PATTERNS · NOT LIBRARIES

Content Cache & Atomic Publish

SHA-256 cache key, atomic rename, serta memory mtime cache membatasi pembacaan parsial dan pengolahan berulang.

How it’s used

Manifest dan wind JSON dipublikasikan secara atomik. Pola lokal ini tidak menyiratkan Redis, Kafka, atau queue daemon.

Engineering choices

01 / SNAPSHOT READS

Kunjungan tidak bergantung FTP

API realtime membaca MySQL; tanggal histori yang belum tercache memakai jalur on-demand tersendiri.

02 / SEPARATE RENDERING

WebGL di luar marker lifecycle

Canvas GPU khusus menangani vektor angin, Leaflet mempertahankan marker dan konteks spasial.

03 / CONSISTENT FILE OUTPUT

Atomic publish dan content cache

Hasil plot serta file angin dibaca setelah publikasi lengkap, dengan cache untuk mengurangi rendering ulang.
