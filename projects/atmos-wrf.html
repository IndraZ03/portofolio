ATMOS / WRF-WEB

Berawal dari kolaborasi bisnis digital, ATMOS tumbuh menjadi tools berbasis web yang mempermudah forecaster menjalankan WRF/WRF-Chem. Antarmuka sederhana dan bantuan AI Agent membantu mengatasi kerumitan konfigurasi model untuk menghasilkan produk cuaca pendukung Operasi Modifikasi Cuaca (OMC).

Partner Bisnis

Yudha Satrio Oktavandi (konseptor) dan Dwi Indra Prasetyo (eksekutor) mengawali kolaborasi melalui bisnis affiliate marketing. Keduanya membangun otomatisasi berbasis bot: video produk dibuat dengan AI, lalu diposting secara otomatis ke TikTok untuk mempermudah proses bisnis.

Dari Bisnis Digital ke WRF

Saat menjalani diklat Modifikasi Cuaca, Yudha mendapat gagasan untuk menerapkan pola otomatisasi dari bisnis digital ke pemodelan atmosfer. Tujuannya mempermudah proses menghasilkan produk cuaca pendukung OMC di tengah keterbatasan pemodelan yang ada.

Latar Belakang Masalah

Menjalankan WRF dan WRF-Chem sulit: dokumentasi terbatas, instalasi panjang, dan forecaster kehabisan waktu hanya untuk menangani error program. Dari situ muncul ide membuat tools yang user-friendly: forecaster cukup melihat tampilan web yang sederhana dan tinggal klik untuk menjalankannya tanpa berhadapan langsung dengan program.

Namelist dan Error Running

Ada dua masalah utama: parameter WRF/WRF-Chem sangat banyak serta pengaturannya rumit. Terdapat setup tertentu untuk WRF-Chem, dan pembuatan namelist.wps maupun namelist.input masih manual sehingga sering error karena pengguna kurang teliti (berdasarkan pengalaman nyata).

AI Agent ATMOS

Indra mengusulkan menambahkan fitur AI Agent yang juga telah membantu dalam pengembangan web ATMOS. AI Agent mampu memberikan saran konfigurasi namelist sesuai produk yang ingin ditampilkan pengguna. Jika terjadi error karena pengisian namelist yang salah, AI Agent ATMOS akan mengoreksi namelist tersebut.

Hal di Luar Ekspektasi

Saat presentasi tugas akhir diklat, penguji dari DMC sangat tertarik. ATMOS kemudian digunakan pada kegiatan OMC dengan memanfaatkan wrfout untuk menghasilkan Cloud Opportunity Index yang dikembangkan Yudha. Hasil prakiraan WRF sangat memuaskan dan mendapat apresiasi Direktur Operasional Modifikasi Cuaca sehingga Yudha diarahkan presentasi di AWWM 2026.

Sempat diragukan oleh Mr. Duncan karena waktu running WRF hanya 2 jam. Namun setelah dijelaskan bahwa domainnya wilayah kecil, jangka waktu pendek, dan resolusi rendah, Mr. Duncan mengapresiasi keterbatasan yang ada.

Keberlanjutan

ATMOS masih digunakan untuk menjalankan WRF dalam kegiatan OMC 09–18 Oktober 2026 untuk menghasilkan produk kelayakan semai higroskopis, Cloud Opportunity Index, laju pertumbuhan awan, dan updraft maksimum.

Alur Kerja Sistem

How It Works

Delapan tahap orkestrasi pemodelan atmosfer numerik dari penyiapan domain wilayah hingga analisis luaran visual NetCDF di antarmuka web.

  1. 01
    Tahap 01 · Workspace

    Create a Project

    Inisialisasi workspace simulasi dengan konfigurasi parameter, penentuan direktori kerja mandiri di filesystem, dan pencatatan metadata proyek di basis data.

  2. 02
    Tahap 02 · Wilayah

    Define Model Domains

    Domain Wizard interaktif berbasis peta mempermudah penarikan batas koordinat wilayah, resolusi spasial, pemilihan proyeksi peta, dan konfigurasi nesting domain (d01, d02) menjadi berkas namelist.wps.

  3. 03
    Tahap 03 · Input Data

    Prepare Input Data

    Pemilihan dan pengunduhan data batas meteorologi global (seperti GFS atau FNL) yang dikelola melalui background download jobs, serta data emisi tambahan untuk kebutuhan pemodelan kimia.

  4. 04
    Tahap 04 · WPS

    Run WPS Preprocessing

    Eksekusi berurutan modul pra-pemrosesan: geogrid memetakan data topografi permukaan, ungrib mengekstrak berkas meteorologi, dan metgrid menginterpolasi data ke domain grid model.

  5. 05
    Tahap 05 · Inisialisasi

    Initialize the Model

    Modul real.exe memproses berkas met_em dan konfigurasi fisika namelist.input untuk menghasilkan kondisi inisial dan batas simulasi (wrfinput dan wrfbdy).

  6. 06
    Tahap 06 · Opsional (WRF-Chem)

    Prepare Atmospheric Chemistry

    Khusus WRF-Chem: preparasi modul kimia atmosfer (seperti bioemisi MEGAN, inventarisasi emisi antropogenik, dan kondisi batas WACCM via mozbc). Simulasi meteorologi standar melewati tahap ini langsung ke eksekusi WRF.

  7. 07
    Tahap 07 · Eksekusi

    Execute WRF Simulation

    Pelaksanaan integrasi numerik dinamika atmosfer menggunakan wrf.exe (MPI parallel processing). Status node, laju integrasi per time-step, dan log sistem dapat dipantau di dasbor hingga menghasilkan berkas NetCDF (wrfout).

  8. 08
    Tahap 08 · Analisis

    Explore & Analyze Results

    Hasil luaran NetCDF dieksplorasi secara visual melalui NC Viewer terintegrasi: peta sebaran parameter 2D, irisan vertikal atmosfer, grafik time series titik observasi, serta kalkulasi Cloud Opportunity Index untuk mendukung kegiatan OMC.

Tahap 01 · Workspace

Create a Project

Catatan sistem: Tahap pemrosesan dijalankan dan dipantau per node (Start / Stop) untuk transparansi komputasi. Tahap Kimia Atmosfer (Tahap 06) bersifat opsional dan hanya diaktifkan untuk riset polutan atau aerosol WRF-Chem.

Kapabilitas Utama

Key Features

Tujuh pilar kapabilitas dalam platform ATMOS yang menjembatani otomasi alur pemodelan atmosfer, pemrosesan numerik intensif, dan analisis spasial berbasis web.

FEATURE 01

Project & Data Management

Organisasi simulasi numerik berbasis direktori independen dan katalog dataset terpadu dengan pelacakan proses unduh asinkron di latar belakang.

  • Struktur workspace modular memisahkan konfigurasi, dataset, dan keluaran NetCDF per proyek.
  • Dukungan katalog dataset multi-sumber: GFS, ERA5, FNL, ECMWF IFS/HRES, WACCM, dan MEGAN.
  • Pencatatan status asinkron download_jobs dengan sinkronisasi otomatis rentang tanggal pada namelist.
FEATURE 02

Interactive Domain Wizard

Konfigurasi batas spasial, resolusi grid, proyeksi peta, dan nesting domain hierarkis secara interaktif berbasis Leaflet tanpa perhitungan manual koordinat grid.

  • Visualisasi spasial langsung untuk parent dan nested domain (d01, d02).
  • Otomatisasi kalkulasi titik tengah, rasio grid spacing, dan parameter proyeksi Lambert/Mercator.
  • Kompilasi instan menjadi berkas konfigurasi baku namelist.wps yang siap diproses geogrid.
FEATURE 03

WRF Execution Dashboard

Dasbor kontrol terpadu untuk mengeksekusi pipeline meteorologi secara transparan per tahap, dilengkapi pemantauan status node dan log real-time.

  • Orkestrasi alur baku berurutan: geogrid → ungrib → metgrid → real → wrf.
  • Kontrol granular per modul (Start / Stop / Restart) untuk investigasi dan diagnostik kendala komputasi.
  • Penyajian tail log ringan dari sistem berkas untuk meminimalkan beban memori browser.
FEATURE 04

Atmospheric Chemistry Modeling

Ekspansi pemodelan cuaca konvensional menjadi simulasi kualitas udara dan aerosol regional dengan integrasi preparasi kimia atmosfer WRF-Chem.

  • Penyisipan modul chem opsional antara real dan wrf tanpa merusak alur cuaca standar.
  • Orkestrasi perangkat kimia: mozbc (kondisi batas WACCM), MEGAN (bioemisi), dan anthro_emis.
  • Dukungan konfigurasi mekanisme kimia atmosfer terdefinisi seperti RADM2SORG.
FEATURE 05

NetCDF Analysis Workspace

Eksplorasi luaran simulasi 3D berformat NetCDF langsung dari peramban web: pemetaan lapisan atmosfer, inspeksi nilai titik, grafik time series, dan irisan vertikal.

  • Kompatibel dengan luaran wrfout, geo_em, met_em, serta berkas NetCDF eksternal.
  • Kalkulasi parameter komposit otomatis, seperti akumulasi curah hujan (RAINC + RAINNC + RAINSH).
  • Fitur irisan vertikal atmosfer dan overlay spasial batas Daerah Aliran Sungai (DAS) serta radar CMAX.
FEATURE 06

Weather Visualization

Transformasi luaran numerik mentah menjadi produk peta cuaca operasional siap pakai dengan palet standar meteorologi BMKG dan komparasi observasi.

  • Pewarnaan kontur curah hujan presisi sesuai standar klasifikasi intensitas BMKG TP.
  • Akses terpadu ke luaran model global operasional ECMWF HRES dan NWP BMKG untuk pembanding.
  • Integrasi layer observasi nyata: kanal inframerah dan True Color Satelit Himawari serta radar cuaca.
FEATURE 07

Execution Monitoring & Project History

Pelacakan komprehensif riwayat eksekusi komputasi panjang, audit konfigurasi namelist, dan pemeliharaan artefak simulasi yang terstruktur.

  • Pembaruan status eksekusi job dan progres iterasi waktu secara efisien via WebSocket.
  • Pemisahan ketat berkas proyek (konfigurasi, data mentah, luaran, dan log) untuk menjamin reproduktibilitas riset.
  • Penghematan ruang penyimpanan disk host melalui pemanfaatan symlink berkas statis geografi dan tabel lookup.

FastAPI Core

APPLICATION · PYTHON ASGI

Asupan / Input HTTP Requests & WebSocket Clients
Luaran / Output PostgreSQL, Local Filesystem, BackgroundTasks

Architectural Decisions

DECISION 01

FastAPI Native Background Tasks vs. Distributed Queue

Tugas berdurasi panjang seperti download data dan pemanggilan model diorkestrasi menggunakan BackgroundTasks internal Python. Menghilangkan kompleksitas operasional Redis atau Celery pada server simulasi mandiri.

DECISION 02

Direct Filesystem Staging for HPC Binaries

Modul numerik WPS dan WRF bekerja langsung membaca dan menulis berkas fisik (GRIB, intermediate, dan NetCDF). Penggunaan disk lokal menjamin throughput I/O tinggi yang esensial untuk perhitungan matriks fluida.

DECISION 03

Modular Symlinked Binaries, Isolated Workspaces

Executable dan tabel geografi statis digunakan bersama melalui symlink sistem berkas, sedangkan konfigurasi namelist, dataset masukan, dan hasil NetCDF diisolasi ketat dalam direktori proyek masing-masing.

Sorotan Rekayasa

Engineering Rationale

Server-Rendered UI vs Heavy SPA

Kombinasi Jinja2 dan Alpine.js menjaga overhead bundle klien tetap nol. Aplikasi fokus pada kendali eksekusi komputasi tanpa beban hydration framework SPA yang kompleks.

Durable Job Telemetry via PostgreSQL & WebSocket

Status eksekusi dan parameter namelist tersimpan aman di database relasional, sementara pembaruan log per detik dihantarkan ringan melalui saluran WebSocket langsung ke browser.

Local Filesystem Throughput for Scientific I/O

Proses numerik menghasilkan puluhan gigabyte data biner per run. Akses disk lokal langsung jauh lebih efisien dibanding abstraksi cloud storage selama fase komputasi aktif berlangsung.

Symlinked Binaries with Isolated Workspaces

Kompilasi binary WPS dan WRF yang berat digunakan bersama melalui symlink sistem berkas, menjamin efisiensi ruang simpan disk seraya mengisolasi penuh direktori luaran per simulasi.
